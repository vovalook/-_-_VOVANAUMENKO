# Сервис учёта удобрений для растений

Индивидуальный проект по дисциплине «Технологии разработки приложений на базе
фреймворков». Тема № 463. Практическая работа № 2.

## Назначение и аудитория

Программа помогает владельцам комнатных и садовых растений вести журнал
использования жидких удобрений. Пользователь добавляет растения и удобрения,
указывает количество в миллилитрах и дату применения.

Это учёт расхода: программа проверяет, хватает ли удобрения в запасе.
Норму подкормки пользователь берёт из инструкции конкретного удобрения.
Отмена предназначена для исправления ошибочной записи: она возвращает расход
в учётный остаток. Фактическую подкормку этим действием отменить нельзя.

## Что изменилось после ПР1

В ПР1 был один ввод растения, удобрения и дозировки. В ПР2 этот сценарий
перенесён в пункт 4 меню и работает с выбранными объектами из справочников.
Функции get_plant_name(), get_fertilizer_name() и check_dosage() сохранены и
переработаны. Условный порог 50 мл заменён проверкой доступного запаса.

Данные теперь представлены словарями и списком словарей, сохраняются в JSON
и восстанавливаются при запуске. Классы и декораторы не используются.

## Возможности

1. Добавление растения; пустые и повторяющиеся названия запрещены.
2. Добавление удобрения с начальным запасом в мл.
3. Просмотр справочников и текущего остатка.
4. Запись применения с проверкой даты, номеров и достаточности запаса.
5. Просмотр журнала.
6. Отмена ошибочной записи с восстановлением остатка.
7. Поиск по части названия растения или удобрения без учёта регистра.
8. Сортировка журнала по дате или дозировке по возрастанию.
9. Статистика: число применений, число растений в журнале, расход по удобрениям.
0. Выход. Каждое успешное изменение сохраняется сразу.

## Структура

- `main.py` — ввод через меню, вывод результатов, обработка ошибок операций.
- `utils.py` — проверка чисел и дат, повторный ввод при ошибке.
- `services.py` — работа с коллекциями, расход, отмена, поиск и статистика.
- `storage.py` — чтение, проверка структуры и запись JSON через `with`.
- `data/database.json` — данные; в поставке файл пустой, без пробных записей.
- `tests/test_services.py`, `tests/test_storage.py` — тесты pytest.
- `requirements-dev.txt` — инструменты проверки.
- `.flake8` — параметры линтера; ограничение строки 79 символов.
- `.vscode/launch.json` — настройка отладки main.py.

## Запуск в Windows

Откройте в VS Code папку, где лежит main.py. Требуется Python 3.10 или новее.
Приложение использует только стандартную библиотеку. Для новой среды:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\python.exe main.py
```

Если `venv` уже создан в ПР1, повторно создавать его не нужно. Команды используют
Python непосредственно из окружения, поэтому активация PowerShell не нужна.

## Проверка

```powershell
.\venv\Scripts\python.exe -m pytest -q
.\venv\Scripts\python.exe -m flake8
```

В подготовленной версии проверены 15 тестовых случаев. Тесты проверяют списание
запаса, невозможность перерасхода, отмену, уникальность номеров, поиск,
сортировку, статистику, неверный ввод, JSON и сохранность файла при ошибке записи.
Тесты используют собственные данные и временные файлы. Пустой вывод flake8
означает, что замечаний нет.

## Формат данных

Корневой объект JSON содержит `plants` и `fertilizers` (словари),
`applications` (список записей) и `next_application_id` (счётчик номеров).
Ключи справочников в JSON — строки с номерами. Запись журнала содержит
`id`, `plant_id`, `fertilizer_id`, `dosage_ml`, `date`.
Дата хранится в формате ГГГГ-ММ-ДД. Счётчик не позволяет повторно использовать
номер последней отменённой записи.

При отсутствии файла программа начинает с пустыми данными. Если JSON повреждён,
программа выводит объяснение и завершает работу, не перезаписывая исходный файл.
Запись сначала идёт во временный файл. Если сохранить не удалось, изменение
не принимается и в памяти. Программа рассчитана на один одновременно запущенный
экземпляр; это учебный проект, а не многопользовательская система.

## Конструкции Python для защиты

- `dict`, `list` — справочники и журнал.
- `tuple` — допустимые значения пунктов и полей сортировки.
- `set` — уникальные номера растений в статистике.
- `while` — меню и повторный ввод; `for` — обработка коллекций.
- `yield` — последовательная выдача найденных записей.
- `lambda` — выбор поля для `sorted()`.
- `try/except`, `raise` — ошибки ввода и правил учёта.
- `with`, `json.load`, `json.dump` — файлы JSON.
- Аннотации типов и docstring — описание функций.
- `__name__` — запуск меню только при непосредственном запуске main.py.

Интроспекцию можно показать командой:

```powershell
.\venv\Scripts\python.exe -c "import services; print(services.check_dosage.__doc__)"
```

## Отладка

В VS Code выберите Python из `venv` и конфигурацию «ПР2 — main.py».
Точка останова: `services.py`, строка `if not isfinite(dosage) or dosage <= 0:`.
Запустите отладку, выберите пункт 4, заполните данные. При остановке видны
`dosage` и `available_ml`. F10 выполняет следующий шаг.

Если расширение Python Debugger не запускается, можно проверить логику через
встроенный `pdb` в терминале. Подробная последовательность приведена в инструкции
к комплекту. Для обязательной демонстрации в IDE исправьте запуск расширения.
